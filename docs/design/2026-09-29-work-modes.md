# 设计方案：Ask / Craft / Plan 三工作模式

> 版本：v1.0（2026-09-29）｜ 状态：待评审
> 对标：WorkBuddy 的 Ask（问一问）/ Plan（想一想）/ Craft（做一做）
> 目标：让用户按任务复杂度选模式——轻量问答不浪费资源，复杂任务先看方案再执行，日常执行直接干

---

## 一、现状盘点（摸底结论）

| 部分 | 现状 | 差距 |
|------|------|------|
| Plan 模式 | ✅ 骨架已存在：`routers/plan.py`（启用开关+SSE）、`plan/hints.py`（计划门控：建计划→展示确认→才放行工具）、前端 PlanPanel + ChatActionGroup 入口 | 藏得深（选项面板里）、默认关、无"模式"概念包装 |
| Ask 模式 | ⚠️ 半成品：`auto_continue_on_text_only` 配置存在，但无"禁用工具纯问答"的独立模式 | 缺一个不挂工具包的轻量执行路径 |
| Craft 模式 | ✅ 就是现有默认行为（ReAct 自主执行+工具） | 只需命名和包装 |
| 模式切换 UI | ❌ 无统一切换器 | 核心新增工作 |

**结论：这是"补全 + 包装"工程，不是从零造**，工期可控。

## 二、模式定义

```
┌────────────────────────────────────────────────┐
│  Ask 问一问（轻）                                │
│  · 不挂任何工具，纯模型对话                       │
│  · 不读不写文件，秒级响应                         │
│  · 适用：咨询、翻译、润色、查知识                  │
├────────────────────────────────────────────────┤
│  Plan 想一想（中）                                │
│  · 先产执行计划 → 用户确认 → 再执行               │
│  · 工具在计划确认前被门控（已有 check_plan_tool_gate）│
│  · 适用：多步骤任务、怕 AI 乱动的场景              │
├────────────────────────────────────────────────┤
│  Craft 做一做（重，= 现有默认）                    │
│  · 直接自主拆解执行，全自动                       │
│  · 适用：熟手、信任度高的重复性任务                │
└────────────────────────────────────────────────┘
```

## 三、技术方案

### 3.1 后端（改动小）

**模式参数**：会话创建请求加 `mode: "ask" | "plan" | "craft"`，存入会话元数据，默认 `craft`。

**Ask 模式实现**（新）：`QwenPawAgent` 初始化时按模式装配——
```python
# react_agent.py 新增逻辑
if session.mode == "ask":
    init_kwargs["toolkit"] = None      # 不注册任何工具
    init_kwargs["max_iters"] = 1       # 单轮直答，不进 ReAct 循环
```
纯对话路径，token 消耗和响应速度大幅优化。

**Plan 模式**（已有，增强）：启用时自动打开现有 plan_notebook 门控；计划确认交互沿用 PlanPanel 的 SSE 通道。

**Craft 模式**：零改动，现有链路。

### 3.2 前端（主要工作量）

**① 模式切换器**（新组件，放输入框左下角）：
- 三段式分段控件：💬问 / 📋想 / 🔨做，一键切换，当前会话内生效
- 每个模式带一行说明文案（首次悬停展示）
- 切换不中断会话——只影响下一条消息的执行方式

**② 模式感知的状态提示**：
- Ask：输入框边框变浅色 + 占位符"快速问答，不调用工具"
- Plan：顶部出现"计划模式"胶囊，计划待确认时高亮
- Craft：默认样式

**③ PlanPanel 优化**（已有组件小改）：计划确认按钮加"确认并执行"主按钮。

### 3.3 不做的事（明确边界）

- ❌ 不按模式计费/积分（WorkBuddy 有，我们暂无计费体系）
- ❌ 不做模式记忆（每会话独立，不跨会话猜测用户偏好——先观察使用分布再说）
- ❌ 不动专家/技能系统（专家会话默认 Craft，保持现状）

## 四、交互示意

```
用户：帮我整理这个文件夹里的发票汇总成表
                ┌──────────────────────────┐
                │ 💬问    📋想    🔨做(选中) │  ← 切换器
                └──────────────────────────┘
[选"想"后发送]
AI：我计划分三步：
     1. 扫描文件夹列出所有 PDF 发票
     2. 逐个提取金额/日期/抬头
     3. 生成汇总 Excel 保存到工作区
    [✓ 确认执行]  [✎ 修改计划]  [✗ 取消]
[用户点确认 → 转入执行，过程同 Craft]
```

## 五、实施排期（估 3~4 个工作日）

| 天 | 内容 |
|----|------|
| D1 | 后端：会话 mode 参数 + Ask 模式装配逻辑 + 单测 |
| D2 | 前端：模式切换器组件 + 输入框状态联动 |
| D3 | 前端：Plan 确认流优化 + 三模式文案（中英） |

## 六、验收标准

1. Ask 模式：发"今天天气如何"→ 无工具调用、2 秒内出字（对比 Craft 模式明显更快）
2. Plan 模式：发复杂任务 → 先出计划，确认前任何文件工具被拦截（日志可见 gate 生效）
3. Craft 模式：现有功能回归全绿
4. 切换器三态切换会话不中断、刷新后保持所选模式
