## v3.2 PYTHONPATH 遮蔽坑（同事日志反查，同日续）✅

**同事现场**: 亲自去部署，SHA256 校验一致但仍"没反应"。T7 盘带回 desktop.log 分析：
- 10:32 两次启动 = 旧包（mcp 版本坑，新包已修）
- 15:20 两次启动 = v3.1 新包，崩在 `ImportError: cannot import name 'builder' from 'google.protobuf.internal' (/usr/lib/python3/dist-packages/...)`——**系统路径**！

**根因（我 v3.1 的锅）**: PYTHONPATH 塞整个 `/usr/lib/python3/dist-packages` 桥接 gi，同事机器装了系统 `python3-protobuf`（老版无 builder），遮蔽 conda 新版 → import 链全断。我的验证容器是裸 Ubuntu 没装这包，所以没复现。

**修复（v3.2）**: 启动器改用 symlink 精准桥接——`ln -sfn /usr/lib/python3/dist-packages/gi $SITE/gi` + 导入自检（import gi 失败即拆）+ typelib 兜底。不碰 PYTHONPATH，不遮蔽任何包。

**验证**: 容器复现套件（系统 protobuf+gi 共存）→ v3.1 确认崩（builder 报错逐字一致）→ v3.2 四项全绿（builder OK/gi OK/gtk 后端 OK/qwenpaw import OK）→ 桌面模式 124+Uvicorn+主窗口 → headless 第 8 秒 HTTP 200。

**新 SHA256**: `684ddb9e26acef8da13f7c495bd086e9b9aa9d5de01717396f9450338f41a08a`（Mac 侧复核一致）。部署说明已同步。

**元教训**: ①跨环境桥接只用 symlink 注入单个包，绝不整目录塞 PYTHONPATH；②裸容器验证 ≠ 目标机能跑，必须装上目标机常见系统 python 包（protobuf/certifi/requests/yaml）再验；③日志乱码（GBK 中文路径）不影响定位，路径里的 site-packages 行号才是关键。

## 本地模型接入方案调研（领导机器，同日续）

**需求**: 部署成功后，领导本地已有一个下载好的模型，如何接入 QwenPaw。

**源码结论**:
- 内置 llama.cpp 集成（`src/qwenpaw/local_models/`）：模型放 `~/.qwenpaw/local_models/models/<子目录>/*.gguf`，`rglob("*.gguf")` 自动发现，目录名即模型 ID
- llama-server 二进制从官方镜像 `download.qwenpaw.agentscope.io`（tag b8744）下载，Linux/mac 仅 **CPU 后端**（`_resolve_backend`）；启动参数 `--gpu-layers auto --alias <模型ID>`
- **内网坑**: llama-server 自动下载走外网域名，内网机器需手动放置 `~/.qwenpaw/local_models/bin/llama-server` + chmod +x
- 非 GGUF 模型备选：Ollama（默认 127.0.0.1:11434，无 key，自动发现）/ LMStudio（:1234/v1）/ 自定义 OpenAI 兼容提供商（设置→模型）
- 建议给同事的落地方案：GGUF → 直接放置重启；safetensors → 转 GGUF 或走 Ollama；需确认领导模型格式和机器内存（7B Q4 ≈ 4.7G 可跑）
